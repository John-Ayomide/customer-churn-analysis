"Initial project setup — folder structure and dependencies"

Commands run and what they do

Step 1 — Create folder structure
mkdir data mkdir notebooks mkdir src mkdir reports
What this does: Creates four empty folders. data/ stores CSV files. notebooks/ holds Jupyter analysis files. src/ is for reusable Python scripts. reports/ is where charts are saved.

Why separately on Windows: PowerShell mkdir only creates one folder at a time unlike Linux/Mac.
Step 2 — Virtual environment
python -m venv venv venv\Scripts\activate
What this does: Creates an isolated Python environment for this project only. Libraries installed here do not affect other projects.

Why this matters: Without venv, all projects share libraries and break each other when versions conflict.

How you know it worked: You see (venv) at the start of your terminal line.
Step 3 — Install libraries
pip install pandas numpy matplotlib seaborn jupyter pip freeze > requirements.txt
What this does: Installs five core data science libraries. pip freeze > requirements.txt saves exact versions so anyone cloning your repo gets identical libraries — making your project reproducible.
Step 4 — GitHub setup
git init git add . git commit -m "Initial project setup..." git remote add origin https://github.com/... git push -u origin master
What each line does:
git init — starts tracking changes in this folder
git add . — stages all files for the next save
git commit -m — saves a snapshot with a message
git remote add origin — connects to GitHub
git push — uploads code to GitHub

Cleaning Summary

Fixed 3 data quality issues. All 11 missing values were brand new customers — not bad data. Final: 7,043 rows x 20 columns, zero missing values.

pd.to_numeric().fillna().map().drop()
"Notebook 2: Data cleaning — fixed TotalCharges, encoded Churn, removed CustomerID"

Every code cell explained

Fix 1 — Convert TotalCharges to number
df['TotalCharges'] = pd.to_numeric(df['TotalCharges'], errors='coerce')
errors='coerce' means: if any value cannot convert, turn it into NaN instead of crashing. Result: dtype changed from object to float64. 11 values became NaN.

Why not .astype(float)? That crashes on any non-numeric character. pd.to_numeric(errors='coerce') handles messy real-world data gracefully.
Investigation — why are 11 values missing?
missing = df[df['TotalCharges'].isnull()] print(missing['tenure'].value_counts())
Finding: All 11 had tenure = 0 — brand new customers who have not been billed yet. Not an error — expected behaviour.

Why investigate before fixing: Without understanding why values are missing you risk making the wrong fix. This thinking is what impresses hiring managers in interviews.
Fix 2 — Fill with 0, Fix 3 — Encode Churn
df['TotalCharges'] = df['TotalCharges'].fillna(0) df['Churn'] = df['Churn'].map({'Yes': 1, 'No': 0})
fillna(0): We fill with 0 not the mean — these customers genuinely have zero charges. Filling with the mean would invent false data.

.map(): Converts Yes/No text to 1/0 numbers. ML algorithms need numbers to calculate with. Convention: 1 = the event happened (churned).
Fix 4 — Drop CustomerID and save
df = df.drop('customerID', axis=1) df.to_csv('../data/churn_cleaned.csv', index=False)
axis=1 means drop a column (axis=0 drops a row). CustomerID is unique per row — no pattern to learn from it, only noise.

Save to new file: Never overwrite raw data. If cleaning goes wrong you need to go back. This is called data provenance.
Purpose of Day 3
In real analyst jobs 60-80% of time is spent cleaning data. The goal is not to fix problems mechanically — it is to understand why each problem exists, make a justified decision, and document it so others understand what was done and why. This is professional-level analytical thinking.
Goal achieved
Transformed a messy raw dataset with 3 quality issues into a clean analysis-ready file. Every decision was investigated and justified. Clean data saved separately from raw — the professional standard. Zero missing values. All correct types.
Alternative approaches
For encoding Churn you could use LabelEncoder from scikit-learn or pd.get_dummies(). For a binary column .map() is most readable. pd.get_dummies() is better for columns with 3+ categories — we use it on Day 6 for Contract Type.

"Notebook 3: Visualisations — churn distribution, contract type, tenure analysis"

Code explained

Chart 1 — Churn distribution
fig, ax = plt.subplots(figsize=(8, 5)) df['Churn'].value_counts().plot(kind='bar', color=['steelblue', 'salmon'], ax=ax) plt.savefig('../reports/churn_distribution.png', dpi=150)
plt.subplots(figsize=(8,5)) — creates a figure of set dimensions. fig is the canvas, ax is the chart area inside. dpi=150 means dots per inch — higher = sharper image. 150 is good for portfolio screenshots, 300 for print quality.
Chart 2 — Churn by contract type
churn_by_contract = df.groupby('Contract')['Churn'].mean() churn_by_contract.sort_values().plot(kind='bar')
groupby().mean() is one of the most powerful pandas patterns. It groups rows by Contract type then calculates the mean Churn value per group. Because Churn is 0/1, the mean IS the churn rate. Month-to-month result: 0.427 = 42.7% churn rate.
Chart 3 — Tenure distribution
df[df['Churn']==1]['tenure'].plot(kind='hist', bins=30, alpha=0.6, color='salmon', label='Churned') df[df['Churn']==0]['tenure'].plot(kind='hist', bins=30, alpha=0.6, color='steelblue', label='Stayed')
alpha=0.6 makes bars semi-transparent so overlapping histograms are both visible. bins=30 divides the tenure range into 30 buckets. The key insight: churned customers (salmon) are heavily concentrated on the LEFT — meaning short tenure = high churn risk.
